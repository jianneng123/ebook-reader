# 电子书阅读器 · 产品设计文档 v0.2（多书书架）

> 状态：已确认 · 待实现｜对应 `docs/PRD.md` v0.1｜更新：2026-11-09｜范围：TXT 多书书架
> 本文只定义 v0.2 的需求、范围与验收；实现方案见 `docs/TECH_DESIGN-v0.2.md`。v0.1 文档保留为历史基线。

## 1. 背景与真正目标

v0.1 是**单书内存态**：`loaded` 只持有一本书，导入新文件直接覆盖旧书；刷新后需重新选文件。用户实际使用方式是一次添加多本、来回切换阅读，v0.1 的交互模型与真实需求错配。

**真正目标**：把「打开一个文件」升级为「拥有一个书架」——书常驻、可自由切换、进度各归各。

## 2. 用户确认的四项决策

| 决策项 | 结论 |
|---|---|
| 持久化 | **存全文，永久保留**。书架列表 + 原始字节写入 IndexedDB，重开后点封面直接读，无需重选文件 |
| 翻页形式 | **分页网格 + 页码**，每页 12 本（4 列 × 3 行），上一页 / 下一页 + 页码指示 |
| 书籍图标 | **自动生成文字书封**，按书名 hash 稳定分配渐变配色并显示书名，模仿微信读书书封观感 |
| 上限与删除 | **满 50 本拒绝导入 + 支持删除**，不自动替换 |

## 3. 功能需求

| # | 需求 | 详细说明 |
|---|---|---|
| R1 | 导入不覆盖 | 新增 TXT 追加到书架；已添加的书全部保留，不再因导入而丢失 |
| R2 | 批量导入 | 文件选择与拖入均支持一次多本 `.txt`；逐本处理并汇总结果 |
| R3 | 去重 | 以**内容指纹**识别同一本书：同一内容不重复添加；同名同大小但内容不同视为两本书 |
| R4 | 来回切换 | 书架 → 点任一书进入阅读 → 返回书架 → 点另一本；无次数限制 |
| R5 | 独立进度 | 每本书独立记忆字符偏移进度，切回时恢复到上次位置 |
| R6 | 独立编码 | 每本书保存自己的编码选择（自动 / UTF-8 / GBK），切换书时互不干扰 |
| R7 | 全局设置 | 字号 / 行距 / 主题仍全局共享，沿用 `reader:settings:v1` |
| R8 | 书架展示 | 网格显示所有已添加文档，每本一个文字书封，图标**下方**显示文件名（含 `.txt`） |
| R9 | 主界面翻页 | 分页网格，每页 12 本；末页不足 12 本正常显示；页码随书数变化 |
| R10 | 上限 50 | 书架最多 50 本；达到上限时拒绝新导入并明确提示，不做自动替换 |
| R11 | 删除 | 每本卡片提供删除入口，二次确认；删除同时清除该书进度 |
| R12 | 主题贯通 | 书架与阅读页均跟随白天 / 夜间主题 |
| R13 | 版本可见 | 界面版本号由 `package.json` 唯一来源驱动，本版为 `v0.2.0` |

## 4. 数据模型（v0.2 增量）

```ts
// 书架条目：存 IndexedDB，原始字节保留以便重新解析与切换编码
type StoredBook = {
  id: string              // 内容指纹（FNV 全字节 + 字节数），取代 v0.1 的 name:size
  title: string           // 文件名去 .txt
  fileName: string        // 原始文件名，用于书架展示
  size: number
  encoding: 'auto' | 'utf-8' | 'gbk'
  buffer: ArrayBuffer     // 原始字节
  addedAt: number
  lastReadAt: number
}

// 进度沿用 v0.1 结构，天然是多书映射
type StoredProgress = { version: 1; books: Record<string, Progress> }
```

**关键决策变更**：v0.1 §6「文件不落库」在 v0.2 被取代。理由：不落库则「添加过的所有文档」在刷新后消失，R1/R4 不成立。v0.1 的 `Locator` 类型、统一书籍模型、解析层解耦约束**继续有效**。

## 5. 交互与界面

```
书架（主界面）
 ├─ 顶部：标题 + 版本徽章 + 「导入 TXT」按钮 + 阅读设置（字号/行距/主题）
 ├─ 网格：每页 12 张卡片（文字书封 / 图标下方文件名 / 阅读进度 / 删除入口）
 ├─ 底部：上一页 · 第 x / y 页 · 下一页
 └─ 点击卡片 → 阅读页
阅读页
 ├─ 顶部：返回书架 + 编码切换 + 阅读设置
 └─ 正文：沿用 v0.1 分块渲染 / 进度 / 百分比跳转
```

- 空书架显示引导文案与导入入口。
- 文字书封配色由书名 hash 稳定生成，同一本书每次打开颜色一致。
- 达到 50 本时提示「书架已满（50/50），请先删除一本」，不静默失败。

## 6. 明确不做

EPUB 解析器、目录树、笔记 / 高亮、全文搜索、云同步、账号、书架排序与分组、拖拽排序、封面图片上传。

## 7. 验收标准

| # | 标准 | 验证方式 |
|---|---|---|
| 1 | 导入 3 本后书架出现 3 张卡片，图标下方显示文件名 | E2E |
| 2 | 刷新 / 重开后 3 本书仍在，点击封面可直接阅读，无需重选文件 | E2E（IndexedDB） |
| 3 | A → 返回 → B → 返回 → A 切换，内容与各自进度正确 | E2E |
| 4 | 导入第 13 本出现第 2 页，上一页 / 下一页可用，页码正确 | E2E |
| 5 | 满 50 本后导入被拒绝并提示；删除一本后可再次导入 | E2E |
| 6 | 删除后该书进度被清除；主题在书架与阅读页一致 | E2E |
| 7 | `file://` 单文件产物仍能渲染，不白屏（IndexedDB 不可用时降级并提示） | Chrome headless |
| 8 | 四条命令全绿、工作区干净、每次改动有 commit | AGENTS.MD |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| `file://` 下 IndexedDB 被禁用 | 书架无法持久 | 检测失败降级为本次会话内存书架并给提示；永久保留在 `http://127.0.0.1` 等常规来源下成立 |
| 50 本长篇占满浏览器配额 | 写入失败 | 写入异常捕获并提示，不静默丢书；对单文件过大给出提示 |
| bookId 变更 | v0.1 旧进度失配 | 一次性迁移代价可接受，写入验收记录已知限制 |
| 内容指纹碰撞 | 两本不同书被判重 | 全字节双 hash + 字节数组成 ID；50 本规模下可忽略 |
| 多选导入中途失败 | 部分书未入架 | 逐本处理并汇总成功 / 跳过 / 失败原因 |

## 9. 交付约定

遵守仓库 `AGENTS.MD`：每次改动配套新增或更新测试，交付前 `python -m unittest discover -s tests -v`、`npm test`、`npm run build`、`npm run test:e2e` 全部通过，并创建对应 Git commit。
